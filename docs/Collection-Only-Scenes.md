# 场景仅采集模式

## 配置步骤

1. 场景维护 → 新建检测场景 → 输入名称，选择 VLM 或流程类型，运行模式选择“仅采集图片”。
2. 进入设计器后发布。此模式无需模型、提示词或完整流程，原有检测配置不会被删除。
3. 数据集维护 → 创建/选择图片数据集 → 采集范围选择“场景 ROI”，关联已发布的场景，开启自动采集并设置上限。
4. 工艺配方编辑 → 绘制 ROI、配置必要的特征点 → ROI 关联该场景 → 发布配方。
5. 外围系统仍调用原来的 `/api/detect`，无需修改入参。可在检测记录和数据集查看采集情况。

场景设计器显示关联数据集、启用状态及自动采集数量。关联在数据集页面维护，设计器可刷新关联。未关联已启用的数据集时发布会提醒，但允许先发布再关联；实际调用会明确失败，不会假装已保存。

## 接口与统计

- 请求包含仅采集 ROI 时，`result` 固定返回 `NG`，包括与正常检测 ROI 混合的请求。
- 素材正常写入、内容重复跳过或达到上限时，接口 `code` 为配置的成功码。`message` 说明未执行质量检测、按约定返回 NG。
- 图片读取、定位、裁剪或素材保存失败，`code` 为异常码，`message` 说明原因，`result` 仍为 NG。失败不影响其他可处理图片的记录。
- 每张有效输入图片对应一个返回路径并保持输入顺序；纯采集图片透传源路径，不生成或上传 `_result` 图片。包含正常检测 ROI 的图片继续画框、上传结果图。
- 场景执行内部结果为 `NOT_INSPECTED`，执行状态区分 `COMPLETED/FAILED`。报表排除采集模式场景版本的所有执行（包括失败记录），混合请求中的正常检测场景仍参与统计。
- 采集项不触发 VLM 复核、不允许人工修改为质量真值；请在数据集中标注图片。场景评测/提示词优化不接受仅采集版本。
- 已发布场景的独立调用接口也支持采集，使用 `image_path`，返回 NG 和原图路径；场景直接调用没有配方，因此采集整张输入图片而不是自动裁剪。

## 保存和版本

`inspection_scenario_versions.definition_json.run_mode` 保存 `DETECT` 或 `COLLECT_ONLY`，缺省为 DETECT；不增加数据库表或字段，无需 DDL 迁移。

采集内容存储在已有 `dataset_items` 表，`source=AUTO_ROI`、`annotation_status=PENDING`、`ground_truth=NULL`。`annotation_json.collection` 保留场景版本、执行编号、ROI、配方、条码、源图路径及裁剪位置。文件沿用 `uploads/datasets/<数据集编码>/auto/`，随机文件名避免多请求覆盖。

按数据集内容哈希去重；数量上限针对未删除的 AUTO_ROI 图片。MySQL 使用目标数据集行锁保护该模式的并发去重和限额检查，文件通过临时文件替换写入。保存失败回滚当前数据集的入库操作并清理该次文件；其他已成功写入的数据集保留，详情逐个显示。

每个目标数据集可显示 `COLLECTED`（已采集）、`DUPLICATE`（重复）、`LIMIT_REACHED`（达到上限）、`DISABLED`（已关闭）、`FAILED`（失败）。测试使用 `PREVIEW`，不新增样本；测试图片不会被自动当成生产数据或合格真值。

模型训练完成后，新建同一场景的草稿版本，切换正常检测，配置模型/流程、测试并发布。新版本发布前仍执行旧版；发布会更新关联 ROI 和数据集的场景版本，确认窗口提示影响的 ROI 数量。历史执行记录继续指向原版本，旧图片与人工标注不变。
